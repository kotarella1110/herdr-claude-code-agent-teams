# Contributing

Thanks for your interest in improving herdr-claude-code-agent-teams. Bug reports, ideas and pull requests are all welcome.

By participating you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md). Report security issues privately as described in [SECURITY.md](SECURITY.md), not in public issues.

## Before you start

- For anything larger than a small fix, open an issue first so we can agree on the approach.
- Claude Code agent teams are experimental. When Claude Code starts issuing a tmux command this plugin does not handle, include the matching `unhandled` lines from `calls.log` (see [Troubleshooting](README.md#troubleshooting)) in the issue.

## Development setup

You need [rustup](https://rustup.rs). The toolchain version is pinned in `rust-toolchain.toml` and installs automatically.

```sh
git clone https://github.com/kotarella1110/herdr-claude-code-agent-teams
cd herdr-claude-code-agent-teams
cargo test
```

To try your build inside herdr:

```sh
sh herdr/install.sh --source
herdr plugin link .
```

## Checks

CI runs the following on macOS and Linux. Run them locally before opening a pull request:

```sh
cargo fmt --all --check
cargo clippy --all-targets --all-features --locked -- -D warnings
cargo test --locked
shellcheck herdr/install.sh
```

CI also scans the whole history for leaked secrets with [gitleaks](https://github.com/gitleaks/gitleaks). To run the same scan locally, install gitleaks and run `gitleaks git --redact .`.

The integration tests in `tests/` drive the real binary against fake `herdr` and `claude` executables, so they need no running herdr. Add a test there when you change how a tmux command is translated.

## Change files

Releases and `CHANGELOG.md` are generated by [knope](https://knope.tech) from change files. If your pull request changes behavior that users can notice, add one:

```sh
cargo install knope --locked
knope document-change
```

Pick `major`, `minor` or `patch` (while the version is `0.x`, `major` bumps the minor version and `minor` or `patch` bump the patch version), write a one-line summary, and commit the generated `.changeset/*.md` file. Add more detail below the heading if it helps. Refactors, tests and CI changes do not need a change file.

Do not edit version numbers or `CHANGELOG.md` by hand; the release pull request does that.

## Pull requests

- Keep each pull request focused on one change.
- Use [Conventional Commits](https://www.conventionalcommits.org) for commit messages and pull request titles, for example `fix: keep teammate panes out of unrelated tabs`.
- Make sure CI passes.
